# 使用案例（繁體中文）

> 🌐 **Languages**: [English](../README.md) | 繁體中文

實際（或仿真）的 Journal Atlas 多輪對話 transcript，展示 AI agent 如何在真實期刊知識庫上推理出投稿戰略。

這些不是抽象的功能列表，而是端到端的展示——當作者描述完一篇論文並要求協助時，skill 實際產出的東西。

## 為什麼有這個資料夾

`SKILL.md` 規範了 AI **應該如何**推理。每一個案例則展示「**這份推理實際長什麼樣**」，包括：

- 作者與 AI 完整的來回對話
- 條件改變（例如「現在我需要 immediate OA」）如何傳遞並改寫整個推薦邏輯
- 拒稿 fallback chain 怎麼被走完
- Comparison mode 如何產出 head-to-head verdict
- AI 如何誠實處理超出 coverage 的領域

對第一次貢獻者來說，這是最快理解「一個好的 Journal Atlas session 長什麼樣」的方式。

## 投稿一個新案例

如果你（或設想中的某人）用 Journal Atlas 跑過一篇真實論文的選刊流程、產出值得展示的對話：

1. 閱讀 [TEMPLATE.md](../TEMPLATE.md)（英文版模板，等中文版貢獻一份雙語版）
2. 把任何會反識別作者的內容匿名化
3. 開 PR

優秀的案例通常具備三個特質：

- **多輪對話**：展示條件改變如何重塑推薦
- **誠實處理 limitation**：至少有一個 AI 承認自己無法處理的時刻（超出 coverage、缺資料、屬性模糊）
- **戰略上有啟發性**：推理邏輯能延伸到具體論文之外

單輪 demo（「給我一個期刊推薦就好」）價值較低。完整走過 skill workflow 的案例最有用。

## 與英文版的關係

中文版與英文版內容對齊——保留所有 verbatim 數據（期刊引用次數、embargo 月份、verdict），但因應中文學術界自然語感調整敘述風格。如果你發現某個版本有錯誤、缺漏或不一致，歡迎開 issue 或 PR。
